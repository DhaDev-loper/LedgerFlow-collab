# WRS Accounting System

A double-entry bookkeeping and cash flow management system for a water refilling station business.

## Tech Stack
- PHP (vanilla, no framework)
- MySQL
- Vanilla HTML/CSS/JS + Bootstrap 5
- PHPMailer (via Composer) for email/OTP

## Setup Instructions

### 1. Get the code
```bash
git clone <your-repo-url>
```
Place it inside your local server's web folder:
- **Laragon:** `C:\laragon\www\`
- **XAMPP:** `C:\xampp\htdocs\`

### 2. Install PHP dependencies
From inside the project folder:
```bash
composer install
```
This installs PHPMailer into a `vendor/` folder (not included in the repo — regenerated by this command).

### 3. Set up your database
1. Start MySQL (via Laragon or XAMPP)
2. Open phpMyAdmin (XAMPP) or HeidiSQL (Laragon)
3. Create a database named `wrs_accounting`
4. Import `backend/database/schema.sql` into it

### 4. Configure environment variables
1. Copy `.env.example` to a new file named `.env`
2. Fill in your own values:
   - Database credentials (usually `root` / no password by default on both Laragon and XAMPP)
   - Gmail SMTP credentials — **you'll need your own Gmail App Password** (see below)

### 5. Create your Gmail App Password (for OTP/password reset emails)
1. Enable 2-Step Verification on your Google Account
2. Go to https://myaccount.google.com/apppasswords
3. Generate an app password, paste it into `.env` as `MAIL_PASSWORD`

### 6. Seed the first admin account
Visit in your browser:

http://localhost/wrs-accounting-collab/backend/database/seeds/seed_admin.php
(adjust the path/domain to match your local server setup)

Default seeded login:
- Email: `admin@wrs.test`
- Password: `password123`

### 7. Access the system

http://localhost/wrs-accounting-collab/frontend/login.html

## Project Structure

frontend/ — all user-facing pages, CSS, JS
backend/ — PHP logic: routes, config, database

## Notes for Contributors
- Never commit `.env` — it contains real credentials
- Always test your changes work with **relative paths** (no leading `/`), since teammates may run this from different subfolder locations
- Run `composer install` after pulling changes that touch `composer.json`
